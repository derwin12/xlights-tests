How it works

  1. The show in show/ is generated by scripts/gen_show.py. It has 15 models covering the common model types, with submodels, a singing face and a state definition, plus groups. It also has DMX fixtures (moving heads, a floodlight, a general fixture and servos) and 22 output variants (node orders, RGBW modes, single-colour strings, dimming curves and start-channel forms). It also has a generated test tone and image. There is one sequence per effect: each steps through the default settings, every value of each choice and all checkboxes flipped, then renders the defaults on a group. Faces, State, Pictures, VU Meter, Music, Duplicate, Video, Moving Head, DMX and Servo have hand-written sequences. The Feature_ sequences cover transitions, layer blending, group buffer styles, buffer transforms, colour adjustments, value curves, effects fired by timing marks, submodels, palette curves, layer morph, sparkles and model output. The Seq_ sequences vary the frame timing and turn off model blending.
  2. Each sequence is rendered with xLights --headless in its own process, so a crash fails only that scenario.
  3. It is rendered a second time, and the two .fseq files must be identical.
  4. The first render is compared with baselines/<name>.fseq using xLights --fseqcmp. A mismatch lists the models that changed.

A change that is meant to alter rendering needs new baselines: run the workflow by hand with rebaseline ticked and it commits the new .fseq files. To add a scenario, extend gen_show.py, regenerate the show, and rebaseline.
